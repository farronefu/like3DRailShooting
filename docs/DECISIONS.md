# 開発開始時の判断

## 確定した要件

ブラウザで動作検証し、将来はSteamでの販売を目指す3Dレールシューティング。マウス・キーボードとゲームパッドの双方に対応。最初の範囲は自機移動、射撃、敵機、当たり判定、3〜5分の1ステージ、障害物、敵機からの攻撃。素材は簡単な図形。リポジトリ名は `like3DRailShooting`。

## 採用した構成

- Godot 4.6 stableのStandard版とGDScript。
- Compatibility renderer。Web側はWebGL 2 / WebAssembly、スレッドなしで出力。
- 同じプロジェクトからWindows x86_64版も生成。
- 物理更新60Hz、描画フレームとは分離。弾は移動区間と球の交差で判定し、高速移動によるすり抜けを防止。
- 自機を基準に敵と背景を移動。進行時間は速度やフレーム数ではなく秒数で管理。
- 背景の構造物は再利用。敵・弾・破片は役割を終えると削除。
- 240秒でクリア、HP制、残機なし、撃墜時は最初から。難易度は固定。
- 入力の上下反転、効果音切替、一時停止を用意。設定保存は後回し。
- UIの仮表記は英語。説明書は日本語。

## ブラウザ先行の効率

ブラウザ専用の実装を別エンジンに移植する方式を取らず、共通Godotプロジェクトを二つのプラットフォームに出力します。そのため、今回の操作・ルール・ステージの試作はWindows版にも引き継げます。
ブラウザには性能・音声・ゲームパッド認識の制約があります。Steam向け製品版の性能や入力対応はWindows実機で継続的に確認する必要があります。

公式資料:
- https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html
- https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_windows.html
- https://godotengine.org/download/archive/4.6-stable/

## 次の試遊で決めること

開発着手を止める必要はない項目です。試遊の結果に合わせて調整します。

1. マウスによる自機移動の感度、上下反転の初期値、パッドのデッドゾーン。
2. 敵を狙いやすいか、弾や障害物を見分けやすいか。
3. 敵弾の速度、HP、回復頻度、初回クリアまでの難易度。
4. バレルロール、ロックオン、チャージショット、ボムなど追加する操作。
5. ボス、分岐、仲間との通信、ステージ数、世界観。
6. 正式なタイトル、UI言語、キー設定、セーブ仕様、対象ゲームパッド。

実績などSteam固有の機能は、ゲームの操作感が固まってから組み込みます。
